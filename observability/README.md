# Observability

```
 backend (Spring Boot)                                           exporters
  OpenTelemetry Java agent  ->  auto-instrumentation              node-exporter, cAdvisor,
  + manual instrumentation      (HTTP, JDBC, Redis, JVM)          mysqld-exporter, redis-exporter,
        |                                                         blackbox (uptime probes)
        | OTLP (metrics)                                                |
        v                                                               v
   OTel Collector  ---- Prometheus remote write ---->  Mimir  <----  Prometheus (agent mode)
                                                         |  blocks stored in an S3 bucket (MinIO)
                                                         v
                                                      Grafana  (dashboards + Grafana-managed alerts -> Gmail SMTP)

 backend stdout (one JSON object per line, includes trace_id / span_id)
   + frontend (nginx), mysql, redis stdout
        |  Docker "fluentd" log driver
        v
   Fluent Bit  ->  Elasticsearch  ->  Kibana   (daily indices ecommerce-logs-*, 7 day retention via ILM)
```

## Start

```bash
cp .env.example .env && docker compose up --build
```

## How the telemetry is produced

* **Auto-instrumentation**: the OpenTelemetry Java agent (`-javaagent`, added in `backend/Dockerfile`) instruments Spring MVC,
  JDBC/Hikari, Lettuce (Redis), the HTTP client and the JVM, and exports metrics over OTLP.
* **Manual instrumentation** (`backend/.../telemetry/`): `BusinessMetrics` (OTel API counters) and `Tracing` (spans around
  payment creation/confirmation and e-mail sending). Business metrics: `ecommerce_orders_placed`,
  `ecommerce_payments{outcome=initiated|replayed|reused|succeeded|failed|already_paid_blocked}`, `ecommerce_revenue`,
  `ecommerce_cache_requests{result=hit|miss|error}`, `ecommerce_ratelimit_rejected`, `ecommerce_notifications{outcome}`,
  `ecommerce_users_registered`, `ecommerce_logins{outcome}`, `ecommerce_cart_items_added`.
* **Structured logs**: `logback-spring.xml` (profile `json`) writes JSON via logstash-logback-encoder. The agent injects
  `trace_id`/`span_id` into every line, and business code adds fields such as `event`, `orderId`, `paymentIntentId`.
  In Kibana try the saved searches *Payment events*, *E-mail notifications*, *Rate-limited requests*, *Errors & warnings*.
* Traces are generated (and correlated into the logs) but **not stored** (`OTEL_TRACES_EXPORTER=none`) because no trace
  backend was requested. To keep them, add Tempo and set `OTEL_TRACES_EXPORTER=otlp` plus a traces pipeline in the collector.

## Alerts (Grafana-managed, e-mail over SMTP)

13 rules in **Ecommerce Alerts**: Node CPU > 40%, Node memory > 40%, **Container CPU > 40% of its limit**, **Container memory > 40% of
its limit**, health probe down, 5xx > 5%, p95 > 1 s, JVM heap > 85%, payment failure ratio > 20%, confirmation e-mails
failing, MySQL connections > 80%, Redis memory > 80%, rate-limit spike.

Container alerts use each container's limit (`deploy.resources.limits`: backend 1 CPU / 1.5 GB, frontend 0.25 CPU / 128 MB,
Redis 0.5 CPU / 256 MB); containers without a limit are covered by the node alerts. E-mails use the same Gmail credentials as the
app (`SMTP_*`) and go to `ALERT_EMAIL_TO`. No Gmail yet? `docker compose --profile mailpit up` and see the comment in `.env.example`.
Trigger a CPU alert: `docker compose --profile tests run --rm k6 run /scripts/stress.js`.

## Using AWS S3 instead of MinIO

Create the three buckets, then in `.env`: `S3_ENDPOINT=s3.<region>.amazonaws.com`, `S3_REGION=<region>`, `S3_INSECURE=false`,
`S3_ACCESS_KEY`, `S3_SECRET_KEY` (or an instance role), and remove `minio`/`minio-init` from `docker-compose.yml`.
Persistence: metric blocks in the bucket; Mimir WAL in volume `mimir-data`; logs in volume `es-data`; Grafana state in `grafana-data`.

## Known limitations

* **Not executed**: authored without Docker/network access. Start the stack in stages
  (`docker compose up minio minio-init mimir otel-collector grafana`, then the ELK part) and check `docker compose logs <svc>`.
* **Metric names**: panels assume the agent's stable HTTP/JVM semantic-convention names (`http_server_request_duration_*`,
  `jvm_memory_used`, ...) and exporter names (`mysql_global_status_*`, `redis_*`, `fluentbit_*`). If a panel is empty, check
  the metric in Grafana *Explore* and adjust `tools/generate_dashboards.py`.
* **Logging driver**: the Docker daemon (on the host) connects to `localhost:24224`, published by the Fluent Bit container. The
  driver is "async" so containers start without it, but early log lines can be lost until Fluent Bit is up.
* Elasticsearch/Kibana run with **security disabled** (local development). Enable `xpack.security` before exposing them.
* cAdvisor / node-exporter need Linux; on Docker Desktop they show the VM and container names may be missing.
* MinIO stopped publishing new community images; the compose file pins an older tag (`MINIO_IMAGE_TAG`).
